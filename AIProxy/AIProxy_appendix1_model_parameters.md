# AIProxy 別紙1　プロバイダ、モデル、パラメータの入力

この別紙は、AIクエリが生成AIの呼び出し先として持つ、プロバイダ、モデル、パラメータについて、定義スタッフの入力方法とシステムの検査をまとめる。用語とユースケースは `AIProxy_requirements.md` に従う。

## 1. 3つの項目

| 項目 | 内容 | 入力の方法 |
|---|---|---|
| プロバイダ | 生成AIを提供する事業者のサービス | 選択肢から選ぶ |
| モデル | プロバイダが提供する生成AIの種類 | 選択肢から選ぶか、モデル名を直接入力する |
| パラメータ | 呼び出しに付ける設定値のセット | JSON形式で入力する |

3つとも、AIクエリの中身の層に属する。変更してもクライアントアプリのソースコードには影響せず、新しい改訂として保存する。

## 2. プロバイダの選択

- プロバイダは、そのステージに接続設定（APIキーなど）があるものから選ぶ。
- 接続設定のないプロバイダは呼び出せないので、直接入力はできない。

## 3. モデルの選択

- スタッフ用Web UIは、過去に指定されたモデル名を、プロバイダごとに整理して、選択肢として示す。
- 選択肢は、定義スタッフの別を問わず、そのステージで指定されたものを集める。
- 選択肢の元になるのは、保存済みのAIクエリと、応答が得られた試行である。失敗した試行は元にしない。打ち間違えたモデル名が選択肢に残ることを防ぐためである。
- 選択肢にないモデルは、モデル名を直接入力する。直接入力したモデルで試行し、応答が得られると、以後は選択肢に現れる。

モデルの一覧を、あらかじめ管理者が登録しておく必要はない。プロバイダが新しいモデルを出したとき、定義スタッフはモデル名を入力するだけで試せる。

## 4. パラメータの入力

### 4.1 形式

パラメータは、プロバイダとモデルの組み合わせごとに、指定できる項目も、項目の名前も違う。項目ごとの入力欄は設けず、JSON形式でまとめて入力する。

入力の例（項目の名前は、プロバイダによって違う）：

```json
{
  "temperature": 0.2,
  "max_output_tokens": 2000
}
```

定義スタッフは、手元の生成AIに、使うプロバイダとモデルを伝えてこのJSONを書かせ、貼り付けることを想定する。

### 4.2 システムの検査

| 検査 | 行う時点 | 合わない場合 |
|---|---|---|
| JSONとして正しいこと | 試行と保存 | 拒否する |
| 指定できない項目が含まれていないこと | 試行と保存 | 拒否する |
| 出力トークン数の上限が、システム保護の上限以下であること | 試行と保存 | 拒否する |

検査で拒否された試行は、生成AIを呼び出していないので、試行ログに記録しない。

個々の項目がそのモデルで使えるかどうかは、システムでは検査しない。使えない項目や値は、試行したときにプロバイダのエラーとして分かる。試行が、パラメータの正しさを確かめる手段である。

### 4.3 指定できない項目

次の項目は、AIProxy が組み立ててプロバイダに送る。パラメータのJSONに書くことはできない。

- プロンプト（テンプレートに変数値を展開したもの）
- モデル名
- 応答形式と応答スキーマ

貼り付けたJSONが、テンプレートや応答スキーマを上書きすることを防ぐためである。項目の名前はプロバイダごとに違うので、指定できない項目の一覧は、プロバイダごとに持つ。

### 4.4 出力トークン数の上限

- システム保護の出力トークン数の上限は、プロバイダごとに持つ。
- パラメータで指定されていない場合は、そのプロバイダの上限を設定する。
- そのプロバイダの上限を超える値が指定されている場合は、試行と保存を拒否する。
- モデルごとの最大値がプロバイダの上限より小さい場合は、試行したときにプロバイダのエラーとして分かる。定義スタッフは、パラメータで小さい値を指定する。

## 5. モデルの提供が終了した場合

プロバイダがモデルの提供を終了すると、そのモデルを指定したAIクエリの実行は、生成AIの失敗として実行ログに記録される。定義スタッフは、別のモデルを指定した新しい改訂を試行し、保存し、有効にする。入出力バージョンは変わらないので、クライアントアプリの改修は要らない。

提供が終了したモデルを指定した過去の改訂は、そのまま残る。実行ログから、当時使われていたモデルとパラメータを引ける。

## 6. 実装設計で定めること

- 対応するプロバイダの範囲
- ステージごとの接続設定の持ち方
- プロバイダごとの、指定できない項目の一覧
- プロバイダごとの、出力トークン数の上限に当たる項目の名前
- プロバイダごとの、停止理由の読み替えと、使用量の内訳からトークン数への読み替え
