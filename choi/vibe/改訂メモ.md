# 改訂メモ — vibe/ 指示書の出典と改訂追跡

`choi/vibe/` の指示書(DATA.md / LOGIN.md / STATUS.md と各添え書き)は、
学習アプリの開発者(生成 AI を含む)に読ませる文書であり、規則の出典や
裁定の経緯を本文に含めない。それらは本書に記録する。本書は指示書の
編集者向けであり、アプリに読ませない。

## DATA.md(教材データ読み込み規約)

- 器の規定は `choi/投稿データ_メディアパック仕様.md` が正本
- API のフィールド名・応答形は実装が正(2026-08-17 裁定)。実装正裁定の
  内容: API 境界は `content` 名・パース済みオブジェクト、空欄列はキー欠落、
  デッキ画像は `image_filename`
- 教材の意味論はファミリーごとの規約(AB会話教材は `choi/ab/AB教材規約.md`)
  に属し、DATA.md は関知しない
- §7 の現物例は開発環境のサンプルユニット `FEB49F42-9A05-11F1-B061-10DC160DA7B8`
  で 2026-08-17 に実測
- 言語解析の分離(issue #444。教材登録時の解析生成の停止、`deck/detail` の
  `analysis` パラメータによる配信)は 2026-08-31 に devel で実測。これに伴い
  §3.2 手順1 の判定条件から `analysis_status` を外し(解析データを用いる
  アプリのみ確認する形へ)、§3.3 に `analysis` / `part_id` / `course_id` を
  列挙した(2026-09-14)。`analysis` の現物例は未収載。解析データを用いる
  アプリが現れた時点で実測して加える
- `analysis_status` が `done` でもデッキ単位で `analysis` が null になりうる
  (解析対象を持たないデッキ・デッキ単位で失敗したデッキは保存せずスキップ
  したうえで、末尾で無条件に `done` にする実装。ゲートキーパー調査
  2026-09-14)。このため DATA.md §4 は「done なら全デッキで非 null」を保証
  せず、用いるアプリ側の中断規定(a: ユニットの状態 / b: デッキの null)で
  受ける
- DATA.md §3.2 の「登録済みの教材に対して事後に実行される」は #444 ④
  (事後実行の操作)が実装された状態を想定して書いている。④ は保留中
  (2026-09-14 時点)で、現行実装には解析を起動する経路が無く、新規登録・
  本文更新を経たユニットの `analysis_status` は `none` のままになる。④ の
  仕様が固まった時点で記述の当否を再確認する
- §5 の CORS 規定(2026-09-14 追加)の根拠: 受け入れテストスレッドが
  cdn.enhack.app の zip URL を、仕様側スレッドが同ホストのルートを、
  `Origin` ヘッダ付きの curl で実測。`Origin: https://devel.enhack.app`
  には `access-control-allow-origin: https://devel.enhack.app` /
  `access-control-allow-methods: GET,HEAD` / `vary: Origin` が返り、
  `https://choi.enhack.app` や外部オリジンには 403 で ACAO なし。
  すなわち任意の `*.enhack.app` ではなく許可リスト方式で、devel 環境では
  アプリの配置オリジン(= API のドメイン)が載っている。ステージング・
  本番の許可リストは未実測(配置オリジンごとに登録が要る想定)。個別
  ファイルパスは実 URL が手元になく未実測だが、CORS 応答はホスト単位の
  設定(エラー応答にも付く)で確認した
