### ✅ 保留P-17（パート階層の扱い）は確定済み（2026-06-10）

投稿システム側コミット **d9f0df6**（「メディアパック仕様: 教材階層のパート層を任意化」）で確定。**方針B（パートを任意のグルーピング層に）** を採用：

- **ユニット→デッキ：`1 : 1..*`**（デッキはユニット＝ブック直下に必ず帰属）
- **ユニット→パート：`1 : 0..*`**（パートは0個以上の任意グルーピング層）
- **パート→デッキ：`0..1 : 1..*`**（デッキは高々1つのパートに帰属。パート無し＝デッキがブック直下）
- ミニブックはパート未使用（デッキがブック直下、パート区切りビューなし）。単語型ブック等は複数パートを持ちうる
- **パートあり/なしはユニット単位で固定（1ユニット内で混在しない）**
- 「唯一の無名隠れパート」案は不要として却下

v15.3 で C-1（多重度・パート注記）／B-1（パート成績を任意化、ユニット成績は「パートを持つユニット＝全パート成績／持たないユニット＝全デッキ成績」を集約）／C-2（階層伝搬）に反映済み。詳細は §7.1.1 参照。

### 配信オブジェクト構造との対応（参考）

投稿システム側で定義された配信オブジェクト構造（`投稿データ_メディアパック仕様.md` §9）：

```
デッキオブジェクト
├ title         ← デッキ.タイトル
├ image         ← デッキ.画像ファイルID
├ analysis      ← 解析オブジェクト
└ body (JSON文字列)
   ├ type        ← "mini" など（配信ペイロード種別）
   └ cards[]
      ├ title    ← カード.タイトル
      ├ image    ← カード.画像ファイルID
      └ talks[]
         ├ person ← センテンス.話者
         ├ en     ← センテンス.英文
         ├ ja1    ← センテンス.直訳
         ├ ja2    ← センテンス.和訳
         └ audio  ← センテンス.音声ファイルID
```

**注意**：配信オブジェクトの `body.type` （"mini"等）は配信ペイロード種別であり、投稿システム側の `デッキ.タイプ`（会話/文）や学習者アプリ側の `デッキ.タイプ`（word/talk/news）とはまた別軸の値である。複雑化を避けるためv15.2では概念モデル上では扱わない。将来必要になったら §8.5 を拡張する。

### v15での「配信コンテナ」の新構造

```
配信コンテナ {
    +enum ターゲット種別 : コース / ユニット / パート / デッキ
    +String ターゲットID
    +enum 種別 : 即時 / 予約
```

- **デッキ** = 単一デッキの配信。例：インバウンドコンテンツ

### v15での「プレイヤー」エンティティ

## 5. v15時点の確定事項

### 3.1 階層構造（7階層、v10から維持）

```
コース ＞ ユニット ＞ パート ＞ デッキ ＞ カード ＞ 会話シーン ＞ センテンス
```

### 3.2 多重度

| 親→子 | 多重度 | 備考 |
| --- | --- | --- |
| コース→ユニット | 1 : 0..* | コース帰属任意 |
| ユニット→デッキ | 1 : 1..* | **デッキはユニット直下に必ず帰属**（v15.3） |
| ユニット→パート | 1 : 0..* | **パートは任意のグルーピング層**（v15.3） |
| パート→デッキ | 0..1 : 1..* | **デッキは高々1パートに帰属**（v15.3・投稿システム d9f0df6） |
| デッキ→カード | 1 : 1..* | |
| カード→会話シーン | 1 : 1..N | 系統依存（C-2参照） |
| 会話シーン→センテンス | 1 : 4..* | 標準4（話者2人×2ターン） |

### 3.3 カード属性（v13から維持）

| 属性 | 型 | 説明 |
| --- | --- | --- |
| タイプ | enum { 語彙系, 企画系, ニュース系 } | デッキ.タイプから決まる |
| 単語種別集合 | Set ⊆ { 一般, タメ } | タイプ=語彙系のときのみ |

### 3.4 学習成果記録（v14踏襲）

**カード成績**（全カードに1件必ず存在）
- ステータス：未学習 / 学習中 / クリア / 弱点（4値）

**単語成績**（語彙系カードのみ・0..1件）
- ステータス：未学習 / 学習中 / クリア / 弱点（4値）

**デッキ成績／パート成績／ユニット成績／コース成績**
- ステータス：未学習 / 学習中 / 習得（3値）
- 階層的に伝搬

### 3.5 判定の基本ルール（v14踏襲・C-2主担当）

各問題種別の判定は **直近2試行の正誤履歴** で行う：

| ステータス | 条件 |
|---|---|
| クリア | 直近2試行が両方正解 |
| 弱点 | 直近2試行が両方不正解 |
| 学習中 | それ以外（試行歴あり） |
| 未学習 | まだ試行していない |

### 3.6 カード習得と階層伝搬（v14踏襲・C-2主担当）

| 系統 | カード習得の条件 |
|---|---|
| 企画系・ニュース系 | カード成績クリア |
| 語彙系 | カード成績クリア＋単語成績クリア |

階層伝搬（v15.3：パート任意化を反映。パートあり/なしはユニット単位で固定＝混在なし）：
```
カード習得（全カード）
　↓
デッキ成績 = 習得（全カードが習得）
　↓
【パートを持つユニット】 パート成績 = 習得（パート内全デッキ）→ ユニット成績 = 習得（全パート）
【パートを持たないユニット（例：ミニブック）】 デッキ成績 → ユニット成績 = 習得（全デッキ）
　↓
コース成績 = 習得（全ユニットが習得）
```
※ 1ユニット内でパート所属デッキとユニット直下デッキが混在することはない（ユニット単位でどちらかに固定）。パートを持たないユニットにはパート成績は存在しない。

### 3.7 配信の構造（v15更新）

**配信コンテナ**
- ターゲット種別 + ターゲットIDで配信対象を表現（ポリモーフィック）
- 4種類のターゲット種別をサポート（コース／ユニット／パート／デッキ）
- 種別：即時／予約
- ステータス：予約中／配信済み

**プレイヤー（v15追加）**
- タイプ：ユニットタイプ／デッキタイプ
- 配信コンテナのターゲット種別と原則対応
- 将来増加可能性あり

**タイムライン**
- 3種類の絞り込みパターン（グローバル／お気に入り／ユニット）

**公開・配信・表示の3軸独立**（B-2主担当）
- 公開状態（デッキ属性、3値enum）
- 表示フラグ（デッキ属性、boolean）
- 配信コンテナ（独立エンティティ）

### 7.1.1 保留P-17の詳細（パート階層の扱い）

**✅ 確定結論（2026-06-10・投稿システム コミット d9f0df6）**：
**方針B（パートを任意のグルーピング層とする）** を採用。最終的な多重度は次のとおり：

```
コース  "1"   *-- "0..*" ユニット    (コース帰属任意)

パート  "0..1" o-- "1..*" デッキ      (デッキは高々1パートに帰属)
```

- ミニブックはパート未使用（デッキがブック直下、デッキ区切りビューなし）。単語型ブック等は複数パートを持ちうる
