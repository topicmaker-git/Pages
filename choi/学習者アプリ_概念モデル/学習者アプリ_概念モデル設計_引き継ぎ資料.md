### 配信オブジェクト構造との対応（参考）

投稿システム側で定義された配信オブジェクト構造（`投稿データ_メディアパック仕様.md` §9）：

```
デッキオブジェクト
├ title         ← デッキ.タイトル
├ image         ← デッキ.画像ファイルID
├ analysis      ← 解析オブジェクト
└ body (JSON文字列)
   ├ type        ← "mini" など（配信ペイロード種別）
   └ cards[]
      ├ title    ← カード.タイトル
      ├ image    ← カード.画像ファイルID
      └ talks[]
         ├ person ← センテンス.話者
         ├ en     ← センテンス.英文
         ├ ja1    ← センテンス.直訳
         ├ ja2    ← センテンス.和訳
         └ audio  ← センテンス.音声ファイルID
```

**注意**：配信オブジェクトの `body.type` （"mini"等）は配信ペイロード種別であり、投稿システム側の `デッキ.タイプ`（会話/文）や学習者アプリ側の `デッキ.タイプ`（word/talk/news）とはまた別軸の値である。複雑化を避けるためv15.2では概念モデル上では扱わない。将来必要になったら §8.5 を拡張する。

### 変更点まとめ

| 変更内容 | 関連図 |
|---|---|
| **「配信」エンティティを「配信コンテナ」に改名** | B-2 |
| **配信コンテナに「ターゲット種別＋ターゲットID」属性を追加**（コース/ユニット/パート/デッキの4種ポリモーフィック） | B-2 |
| **「プレイヤー」エンティティを新規追加**（タイプ：ユニットタイプ／デッキタイプ） | B-2 |
| **「ミニブック」→「ユニット」用語統一**（議事録引用箇所のみ原文併記） | 全資料 |
| **配信前提条件をターゲット種別ごとに整理** | B-2 |
| **旧概念図用語の用語マッピング表追加**（配信設定、学習マーク等） | 引き継ぎ資料 |

### v15での「配信コンテナ」の新構造

```
配信コンテナ {
    +enum ターゲット種別 : コース / ユニット / パート / デッキ
    +String ターゲットID
    +enum 種別 : 即時 / 予約
    +enum ステータス : 予約中 / 配信済み
    +Date 配信予約日時
    +Date 配信日時
}
```

ターゲット種別ごとの典型ユースケース：
- **コース** = コース全体を配信（将来用）
- **ユニット** = ユニット単位（旧称ミニブック）配信。例：「英語を英語で学ぶ」
- **パート** = パート単位で配信（将来用）
- **デッキ** = 単一デッキの配信。例：インバウンドコンテンツ

### v15での「プレイヤー」エンティティ

```
プレイヤー {
    +enum タイプ : ユニットタイプ / デッキタイプ
}
```

- 学習者が学習を進める際のUI再生コンポーネントの種別
- 配信コンテナのターゲット種別と原則対応
- 将来増加可能性あり

## 5. v15時点の確定事項

### 3.1 階層構造（7階層、v10から維持）

```
コース ＞ ユニット ＞ パート ＞ デッキ ＞ カード ＞ 会話シーン ＞ センテンス
```

### 3.2 多重度

| 親→子 | 多重度 | 備考 |
| --- | --- | --- |
| コース→ユニット | 1 : 0..* | コース帰属任意 |
| ユニット→パート | 1 : 1..* | |
| パート→デッキ | 1 : 1..* | |
| デッキ→カード | 1 : 1..* | |
| カード→会話シーン | 1 : 1..N | 系統依存（C-2参照） |
| 会話シーン→センテンス | 1 : 4..* | 標準4（話者2人×2ターン） |

### 3.3 カード属性（v13から維持）

| 属性 | 型 | 説明 |
| --- | --- | --- |
| タイプ | enum { 語彙系, 企画系, ニュース系 } | デッキ.タイプから決まる |
| 単語種別集合 | Set ⊆ { 一般, タメ } | タイプ=語彙系のときのみ |

### 3.4 学習成果記録（v14踏襲）

**カード成績**（全カードに1件必ず存在）
- ステータス：未学習 / 学習中 / クリア / 弱点（4値）

**単語成績**（語彙系カードのみ・0..1件）
- ステータス：未学習 / 学習中 / クリア / 弱点（4値）

**デッキ成績／パート成績／ユニット成績／コース成績**
- ステータス：未学習 / 学習中 / 習得（3値）
- 階層的に伝搬

### 3.5 判定の基本ルール（v14踏襲・C-2主担当）

各問題種別の判定は **直近2試行の正誤履歴** で行う：

| ステータス | 条件 |
|---|---|
| クリア | 直近2試行が両方正解 |
| 弱点 | 直近2試行が両方不正解 |
| 学習中 | それ以外（試行歴あり） |
| 未学習 | まだ試行していない |

### 3.6 カード習得と階層伝搬（v14踏襲・C-2主担当）

| 系統 | カード習得の条件 |
|---|---|
| 企画系・ニュース系 | カード成績クリア |
| 語彙系 | カード成績クリア＋単語成績クリア |

階層伝搬：
```
カード習得（全カード）
　↓
デッキ成績 = 習得 → パート成績 = 習得 → ユニット成績 = 習得 → コース成績 = 習得
```

### 3.7 配信の構造（v15更新）

**配信コンテナ**
- ターゲット種別 + ターゲットIDで配信対象を表現（ポリモーフィック）
- 4種類のターゲット種別をサポート（コース／ユニット／パート／デッキ）
- 種別：即時／予約
- ステータス：予約中／配信済み

**プレイヤー（v15追加）**
- タイプ：ユニットタイプ／デッキタイプ
- 配信コンテナのターゲット種別と原則対応
- 将来増加可能性あり

**タイムライン**
- 3種類の絞り込みパターン（グローバル／お気に入り／ユニット）

**公開・配信・表示の3軸独立**（B-2主担当）
- 公開状態（デッキ属性、3値enum）
- 表示フラグ（デッキ属性、boolean）
- 配信コンテナ（独立エンティティ）

### 8.5 デッキ.タイプの2軸対応（重要）

**投稿システム側と学習者アプリ側でデッキ.タイプの値が異なるが、これは別軸の概念**：

| 概念モデル | 値 | 意味 |
|---|---|---|
| **投稿システム** | 会話 / 文（2値） | デッキ内のセンテンス構造の分類 |
| **学習者アプリ** | word / talk / news（3値） | プレイヤータイプ（学習者UI上の再生方式） |

これらは概念的に異なる軸：
- 投稿システムの「会話/文」はコンテンツ構造（センテンスの並べ方）の区別
- 学習者アプリの「word/talk/news」は学習者アプリ実装ソース（DialogFlashCards系）由来の値

実装上のおおまかな対応（要確認）：
- 投稿システム「会話」 ⊃ 学習者アプリ「talk」「news」（会話形式は企画系・ニュース系の両方に対応）
- 投稿システム「文」 ⊃ 学習者アプリ「word」（文形式は語彙系に対応）

**保留P-14**：両軸の厳密な対応関係は要確認。投稿システム側の「会話/文」と学習者アプリ側の「word/talk/news」のマッピング規則を明文化する必要あり。
