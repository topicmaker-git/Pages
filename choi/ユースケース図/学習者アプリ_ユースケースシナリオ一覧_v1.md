## 0. 本資料の位置づけ

各ユースケースについて以下を簡潔に記述する。詳細フローは実装フェーズで詳細化する。

| 項目 | 記述粒度 |
|---|---|
| UC名／番号 | Pages.md 由来は UC番号付き、v13新規は名称のみ |
| 主アクター | アクター整理 v1.1 §3 のアクター名で参照 |
| 事前条件 | 認証状態・関係性・属性条件 |
| 基本フロー | 3〜5行で主要ステップ |
| 代替・例外 | あれば1〜2行で言及 |
| 関連UC | include／extend／関連性 |

### UC-N1.1 新規登録（メール＋パスワード）

| 項目 | 内容 |
|---|---|
| 主アクター | ゲスト |
| 事前条件 | ログインしていない |

## 2. U-2 契約・課金

### UC-N2.1 プランを契約する

| 項目 | 内容 |
|---|---|
| 主アクター | 無料会員 |
| 事前条件 | ログイン中・契約なし |
| 基本フロー | ①プラン契約画面を開く ②カード情報を入力 ③契約実行 ④初回ならトライアル7日間開始／2回目以降は即課金 |
| 代替フロー | トライアル使用済 → 即課金開始（メール「契約完了・トライアルなし版」） |
| 例外フロー | カード決済失敗 → エラー |
| 関連UC | extend: トライアル満了で有料へ自動移行（システム） |

### UC-N2.2 カード情報を変更する

| 項目 | 内容 |

| 事前条件 | ログイン中・契約中 |
| 基本フロー | ①アカウント設定>プレミアムプラン>クレジットカード情報の更新 ②新カード情報入力 ③更新 |
| 代替フロー | 滞納状態からの復帰 → 即時再試行 |
| 関連UC | extend: 支払い滞納でサービス停止（条件付き） |

### UC-N2.3 トライアル期間中にキャンセルする

| 項目 | 内容 |

### 《システム自動》UC-N2.8 支払い滞納でサービス停止

| 項目 | 内容 |
|---|---|
| 主アクター | システム（受動UC） |

| 基本フロー | ①停止予告メール ②停止日にサービス停止 ③無料会員相当へ移行 |
| 関連UC | 再契約時はトライアル不適用 |

### 《システム発火》UC-N2.9 契約関連メール通知を受領する（12種類）

|---|---|
| 主アクター | 会員（受動UC） |
| 事前条件 | 各種契約イベント発生 |
| 基本フロー | ①イベント発生 ②該当メールテンプレートで送信 ③ユーザー受信 |
| メール種類 | 12種：契約完了（トライアル有/無）、トライアル開始、トライアル中キャンセル完了、トライアル終了3日前予告、トライアル終了＆課金開始、支払い成功、支払い失敗、カード変更完了、解約完了、アカウント削除に伴う解約、停止予告、サービス停止 |
