# AB教材規約 — AB会話教材ファミリーのデータ規約

## 0. 位置づけと正本関係

本書は、AB会話教材(万次郎語アプリ系)をちょい英語ミニブック投稿システムで
配信するための、**変換ツール(AB → ミニブック投稿形式)と消費側アプリ
(ミニブック → 内部形式アダプター)のペア内合意の正本**である。

- 投稿システムは AB の意味論を一切知らない(不可知コンテナ路線)。
  デッキタイプは `mini` のままであり、投稿データ_メディアパック仕様
  (以下「投稿仕様」)の本文に AB という語は存在しない
- **器(列構成・セル値正規化・拡張属性列の形式・zip 構造・body 出力)の
  正本は投稿仕様**。本書はその上に乗る**中身(意味論)の正本**であり、
  投稿仕様 §1.7.2 が「スコープ外」と定めた拡張属性の記法規約・スキーマを
  ここで定める
- 変換ツール側の実装要件は `変換ツール要件.md`(同区画)が定める。
  本書と重複する規定は本書が正

## 1. 階層写像

AB教材の概念をミニブックの階層(投稿仕様 §1.3)へ次のとおり写像する。

| AB概念 | ミニブック概念 | 識別キー(エクセル列) | 備考 |
|---|---|---|---|
| カテゴリー | ユニット | —(ユニットは投稿単位) | カテゴリー3値で3ユニットに分割。ユニットの名前・category 属性は投稿 UI 設定(投稿データ外)で、カテゴリー列の値を用いる |
| — | パート | —(不使用) | パート列・パート編集ID列は出力しない |
| テーマ | デッキ | チャプター名 = テーマ和名 | テーマ英名・和名の対はデッキ属性(§3)で運ぶ |
| セット | カード | シーン名 = 「セット{k}」(§4) | 1セット = 元データ1行(1 ID) |
| 発話 | センテンス | データ行(1行 = 1発話) | 1カード = 6行(§2) |

デッキ・カードの表示順はエクセル内での登場順(投稿仕様 §1.3)であり、
元データのテーマ・ID の登場順をそのまま保存する。

## 2. 話者と行順

- 「話者」列の値は **A / 類似A / B / 類似B の4値**のみ
- 1カードは**6行周期**で、行順は次で固定する:

| 行 | 話者 | 内容 |
|---|---|---|
| 1 | A | 本会話 A側 |
| 2 | B | 本会話 B側 |
| 3 | 類似A | 類似フレーズ A側 1 |
| 4 | 類似B | 類似フレーズ B側 1 |
| 5 | 類似A | 類似フレーズ A側 2 |
| 6 | 類似B | 類似フレーズ B側 2 |

- この行順により**奇数行 = A側・偶数行 = B側**となり、投稿仕様 §3.3 の
  偶奇フォールバック(TTS ボイス解決)とも整合する(AB教材の本線は
  メディアパックモードだが、規約として行順の不変条件に含める)
- 消費側は `talks[].person` の4値と6行周期を前提としてよい

## 3. 拡張属性(extra)スキーマ

投稿仕様 §1.7.2 の拡張属性列に載せる JSON のスキーマを、本節で正本化する
(設計14 サンプル `sample/sampleS_unit.xlsx` の実装値からの昇格)。

### 3.1 デッキ属性(→ `body.extra`)

```json
{"title_en":"English for Yoroshiku","title_ja":"よろしく、英語なら？"}
```

- `title_en`: テーマ英名(string)
- `title_ja`: テーマ和名(string)。チャプター名列と同じ値
- デッキの先頭行のみ記入(投稿仕様 §1.7.2)

### 3.2 カード属性(→ `cards[].extra`)

```json
{"speakers":{"A":"28歳、女性、オフィス、新入社員","B":"41歳、男性、オフィス、上司"}}
```

- `speakers.A` / `speakers.B`: 話者プロファイルの**生文字列**(自由文)。
  変換ツールが音声生成プロンプトの素として用いたものをそのまま保存する。
  消費側での用途は表示・話者演出等(構造化はしない)
- カードの先頭行のみ記入(投稿仕様 §1.7.2)

### 3.3 スキーマ適合の定義と共通規定

- **必須キー**: デッキ属性は `title_en` / `title_ja`、カード属性は
  `speakers` およびその配下の `A` / `B`。いずれも値は**非空文字列**
- **生成側**(変換ツール)は本書の定義キーのみを出力する(未定義キーの
  出力禁止。変換ツール要件 §6 検査5 の「スキーマ適合」はこの2条 —
  必須キー充足かつ定義キーのみ — を指す)
- **消費側**は未知キーを無視すること(前方互換)。キーの追加は本書の改訂
  (末尾追記)による。既存キーの意味変更・削除はしない

- JSON は**ミニファイ**して記入し、空白の忠実性が必要な文字列値は
  エスケープ表記を用いる(投稿仕様 §1.7.2)
- 消費側が受け取る `body.extra` / `cards[].extra` は **JSON 文字列値**で
  あり、**二段パース**が必要(投稿仕様 §9.1 / §9.2)。`extra` キーは
  記入がある場合のみ出力される(デッキ側は投稿仕様 §9.1、カード側は
  §9.2 のフィールド欠落規定)

## 4. カードタイトル(シーン名)

- シーン名は **「セット{k}」の機械命名**とする。k は**デッキ(テーマ)内の
  登場順連番(1起点)**であり、元データの ID ではない
- 元データ ID はメディアファイル名(§6、変換ツール要件 §4・§5)が保存する。
  表示名(セット番号)と同一性(ID)を分離するための規定である
- 本規定は設計12 のサンプルデータ作成指示書 §3(シーン名 = デッキ内の
  登場順で機械命名)・§8 検査6(デッキ内で「セット1..n」の連番)で
  既決であり、本書はそれを正本へ昇格したもの
- 注: 設計14 サンプルの生成スクリプトは「セット{元ID}」で実装されて
  いるが、単一デッキ・ID 1〜5 のため「セット{デッキ内連番}」と結果が
  一致しており、現物に規約との差は現れていない。全量変換では本規定
  (デッキ内連番)に従うこと(元 ID はグローバル連番のため、元 ID 基底
  ではテーマ2以降が「セット6」始まりになる)

## 5. チャンク記法

- 「英会話」(`talks[].en`): チャンク境界を **` / `(半角スペース+
  スラッシュ+半角スペース)**で区切る
- 「手順3で作成した語順訳」(`talks[].ja1`): チャンク境界を**半角スペース**で
  区切る(保存形。投稿仕様 §1.7.1 の正規化により保存形に全角空白は
  存在し得ない)
- **1対1対応**: 同一行の英文スラッシュ数 = 語順訳の半角スペース数
  (チャンク数の一致)。消費側はこの対応で en / ja1 のチャンクを
  突き合わせてよい
- 「和訳」(`talks[].ja2`): **不存在**。エクセルでは空欄とし、body では
  出力されない(キー欠落。投稿仕様 §9.2)。消費側は ja2 を
  使用しない

## 6. メディア

- **音声**: メディアパックモード(投稿仕様 §3。`audio_mode=pack` は
  API 側のパラメータ名)。全行が「音声ファイル」列を持つ
  (1発話 = 1音声)。命名は元データ ID 基底(変換ツール要件 §4)
- **画像**: 同じくメディアパックモード(API 側 `image_mode=pack`)。
  デッキ画像・カード画像は**テーマ画像への
  多対一参照**とする — 各デッキの先頭行と、そのデッキ配下の各カードの
  先頭行が、同一のテーマ画像ファイルを参照する(投稿仕様 §1.6 が同一
  ファイル名の複数行参照を許容)。セットのトビラがテーマ画像を表示する
  プロトタイプの現行挙動の忠実なデータ化である
- スプラッシュ画像はユニットカバー(`cover`、投稿 UI 設定)に対応し、
  投稿データ外。話者ポートレート・口形(lipsync)はアプリ側資産で
  教材データ外

## 7. サンプル(現物)

`sample/` に設計14 で作成・引き渡し済みの現物一式を収める
(実装サイドへ 2026-08-06 送付済みのものと同一)。

| ファイル | 内容 |
|---|---|
| `sampleS_unit.xlsx` | 投稿用エクセル(14列 × 30データ行。ID 1〜5 = 1デッキ5カード) |
| `audio.zip` | **実音声** mp3 30本(フラット構成) |
| `image.zip` | `theme001.png` 1枚 |
| `gen_sample_s.py` | 生成スクリプト+出口検査(条文単位) |
| `audio_rename_map.tsv` | プロトタイプ音声名 → 投稿名の対応表(30件・manifest キー付き) |
| `make_real_audio_zip.sh` | プレースホルダ無音を実音声に差し替える手順 |

- **再現条件**: 再生成には private のプロトタイプ資産(元エクセル
  `source_ab.xlsx`・`manifest.json`)が必要で、Pages 単体では再生成
  できない。スクリプト内のパスは作成時のコンテナ絶対パスであり、
  実行時は環境に合わせて読み替える
- サンプルのシーン名は §4 注記のとおり実装が元 ID 基底(単一デッキの
  ため規約のデッキ内連番と結果一致)
