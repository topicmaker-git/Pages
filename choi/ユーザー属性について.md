# 会員属性と編集責務(ユーザー属性について)

会員(アカウント)の属性の出自と、ちょい英語本体 / 団体コンソールの
どちらで表示・編集するかの責務区分を定める。単一情報源は本ファイル
(概念モデル図の Account ノートは要約。メール合意 2026-07-27 に基づく)。

## 外部環境: 属性の3層構造

すべての基盤は enHack アプリであり、ユーザーアカウントも enHack による
認証がベースになっている。

1. **enHack 層(認証基盤)**: ユーザーID(`User.id`)、メールアドレス、
   パスワード、OAuth連携。enHack はメールアドレス + パスワード認証と
   OAuth連携認証をサポートする
2. **ちょい英語 profile(初期定義)**: enHack から派生した「ちょい英語」の
   ローカル属性として `profile`(初期は null)が定義された:
   `name`(名前)/ `introduction`(紹介)/ `url` / `icon`
3. **本サブシステムでの拡張**: 団体という概念の導入に伴い profile を拡張:
   - `nickname` を**新設**。ちょい英語本体のユーザー登録フローで
     「ニックネーム」として入力される値の登録先を、従来の `name` から
     `nickname` に変更する(**決定済み**。大川さん側で整備予定)
   - これに伴い `name` は**「氏名」として再定義**(団体が管理する実名。
     招待フロー_団体.md 設計判断8・設計ポイント7 の「氏名」はこれを指す)
   - `department`(所属部署)/ `phone`(電話番号)/ `mobile`(携帯電話
     番号)/ 団体ロールを追加

なお、ちょい英語は未リリース(開発途上)のプロジェクトであり、本サブ
システム(団体コンソール + ミニブック投稿システム)はそこに追加される。

## 属性 × 編集責務マトリクス

| 属性 | 層 | ちょい英語本体 | 団体コンソール |
|---|---|---|---|
| ユーザーID | enHack | —(非表示) | 表示のみ |
| メールアドレス | enHack | 表示・編集 | 表示のみ |
| パスワード | enHack | 表示・編集 | — |
| OAuth連携 | enHack | 表示・編集 | — |
| ニックネーム | profile(拡張) | 表示・編集 | 表示・編集 |
| 氏名 | profile(再定義) | — | 表示・編集 |
| 所属部署 | profile(拡張) | — | 表示のみ |
| 団体ロール | 本サブシステム(拡張) | — | 表示のみ(変更は A-M2 で団体管理者のみ) |
| 電話番号 | profile(拡張) | — | 表示・編集 |
| 携帯電話番号 | profile(拡張) | — | 表示・編集 |
| アイコン | profile(初期) | 表示・編集 | 表示のみ |
| 自己紹介 | profile(初期) | 表示・編集 | 表示・編集 |
| URL | profile(初期) | 表示・編集 | 表示・編集 |

- アイコンの編集は本体のみで扱う(団体コンソールでは表示のみ)。
  **原メモ(2026-07-27 メール)では編集可の読みだったが、2026-07-28 の
  高橋さん裁定(設計10 スレッド)で表示のみに変更**した。理由:
  アイコンの差し替えはファイルアップロードを伴い、他のプロフィール編集
  (テキスト系フィールドの一括更新 `POST /user/profile/update`)とは
  **別 API** になるため。コンソール側にアップロード経路を重複実装せず、
  既にその経路を持つ本体側に寄せる
- 属性名の正本表記は「電話番号」「携帯電話番号」。画面ラベルは実装準拠の
  短縮形(「携帯番号」)を許容する
- 認証系(メールアドレスの変更・パスワード・OAuth)は本体のみで扱う。
  団体コンソールのプロフィール画面(A-P1)からは「メールアドレスと
  ユーザー認証設定はこちら」等の文言で本体プロフィール画面へ誘導する
- 所属部署の値は招待時の入力(承諾時反映)または団体管理者の編集
  (A-M2)に由来し、本人はコンソール上で表示のみ

## 関連する決定・仕様との接続

- **承諾時の profile 反映**: 団体招待の承諾時、招待に記載された氏名・
  所属部署を `profile.name` / `profile.department` に反映する(記載の
  ある項目のみ・既存値も上書き)。正本は 招待フロー_団体.md
  設計ポイント7、被招待者への開示はワイヤーフレーム修正仕様 §8.6
- **会員検索との関係**: 指名招待の検索はニックネーム(前方一致)を、
  コース招待の selected 検索は加えて氏名(前方一致)を検索キーに使う
  (ワイヤーフレーム修正仕様 §9.0e / §10.0c)
- **A-P1(トピックメーカー専用暫定プロフィール画面)**: 本マトリクスの
  団体コンソール列を実装する画面。修正指示はワイヤーフレーム修正仕様
  §16
