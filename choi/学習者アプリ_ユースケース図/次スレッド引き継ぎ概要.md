## 1. プロジェクト概要

### 1.1 何を作っているか

**ちょい英語ミニブック** という英語学習サービスの **学習者アプリ** の設計。

サービスは2つのアプリで構成される：
- **投稿システム**：教材を作成・管理する側（A画面群、団体管理者・主催者・投稿者向け）
- **学習者アプリ**：教材を学習する側（B画面群、学習者向け） ← **本スレッドの対象**

## 2. このスレッドで確定した主要な設計判断

### 2.1 アクター構造（4軸モデル）

```
ゲスト（未認証）
   ↓ 認証
会員（抽象基底、図には登場させない）
   ├─ 軸1：団体所属 = 無所属／一般／管理者（属性的制約。UCを直接駆動しないが、U-5には線あり）
   ├─ 軸2：契約状態 = 無料／トライアル／有料／解約手続中
   ├─ 軸3：学習    = 学習者
   └─ 軸4：投稿    = 投稿者

別途、U-5 局所アクター：コース主催者
コースメンバー：アクター化せず（投稿者の一形態として事前条件で識別）
```

**重要な議論メモ：**
- **C-β 採用**：「コース主催者は U-5 図内の局所アクター」として残す（軸とは別の文脈アクター）
- 「軸3 関与」を学習と投稿の2軸に分割した（軸3=学習、軸4=投稿）
- 軸1 → U-5 のみ線を引く（コース運営は団体所属が前提のため）

### 2.2 配信モデル（v15 概念モデル対応）

- 「配信」→「配信コンテナ」に改名
- ターゲット種別＋ターゲットID のポリモーフィック構造
- 配信単位は4種：コース／ユニット／パート／デッキ
- **(D) 自動配信ロジック**：新規ユニット公開時、ユニットの対応プレイヤータイプに応じて自動配信
  - ユニットタイプ → ユニット配信コンテナ自動作成
  - デッキタイプ → 最初のデッキ配信コンテナ自動作成
- タイムラインにはユニット配信とデッキ配信が混在
- 配信UCは汎化（即時／予約／停止 の3UC）

### 2.3 コースメンバーの位置づけ

## 6. 既知の技術的Tips

### Mermaid 構文の注意

- `.mmd` ファイルには **設計判断メモを書かない**（`%%` コメントブロックを長く連続させるとパーサーが壊れる）
- ラベル内の **半角括弧・コロン・スラッシュは避ける**（全角に置換）
- 入れ子 subgraph は動くが、複雑になりすぎるとパーサーが壊れることがある
- 構文チェックは `mermaid.parse(c, { suppressErrors: false })` で行う

### ZIP UTF-8マーカー

- Python の zipfile は ASCII 名にも flag_bits=0x800 を自動セットしない仕様
- macOS / 新しい Windows では問題ないが、古い Windows で文字化けする
- 対策：バイナリ書き換え（PK\x03\x04 の offset+6、PK\x01\x02 の offset+8）で flag_bits を強制セット
- 全エントリ（特に ASCII 名の `index.md` 等）に強制付与する処理を入れる

### ファイル運用ルール

- 出力先：`/mnt/user-data/outputs/`
- 既存ファイルを置き換える場合は先に `rm` する
- present_files で Unicode エスケープを使う場合は注意（俯瞰=U+4FEF を 俺=U+4FFA と間違えやすい）
