### 運用ルール(全スレッド共通・踏襲)

- **確認 → 合意 → 編集 → grep/レンダリング検証 → 出力**。黙って方針を変えない
- **単一情報源原則**。同じ規則を複数箇所に書くときは正本を1つ決め、他は参照
- 整合チェックは grep での一括突き合わせ
- **API 正**(佐藤さんの API ドキュメントが正)。ただし API 内部矛盾は「書き損じ」を特定のうえ確認
- **仕様を書く前に実装の現況を確認する(設計9で追加)**。「仕様未確定」に見える
  論点でも、実装側が既に設計判断を済ませていることがある。要求を新規に決めるのか、
  既決を文書に写すだけなのかを最初に切り分けること
- 佐藤さん管轄(`org_invitation.md` / `course_invitation.md`)は**読み取り専用**
- 番号(§・UC・画面ID・エッジID)は**付け替えず末尾追記**。削除時は欠番として明記。
  **枝番(例: §9.0b〜§9.0e)で挿入する**。挿入前に該当番号の既存有無を grep すること
- WF修正仕様 = Claude Design 向け指示書。画面遷移図 SVG 4枚 = **Claude が直接編集**(viewBox `0 0 1123 794`)
- 編集後は毎回ハングル混入チェック(過去に混入事故があったため)

### 運用ルール(設計10 で追加)

- **WF は常に描画済みでゲートキーパーに渡る**。画面に関わる仕様は最初から
  「描画済み」の規定形で書き、Claude Design 向けの一時指示書(修正内容 +
  検収基準)を毎回添える。高橋さんが描画を済ませてから一式をゲートキーパーに
  渡す運用のため、「再描画対象」マーカーで未描画状態を管理しない。未描画の
  明示は、描画後チェックで漏れが発覚した場合の例外扱いのみ
- **mermaid のノード追加時は、図中の使用済み ID を機械列挙してから採番する**。
  同一 ID の再定義は mermaid では合法(同一ノード参照・ラベル後勝ち)のため、
  レンダリング検証では衝突を検出できない(設計10 で E4 衝突が発生)
- **画面の修正指示は「WF 現物」と「実装」の両方に突き合わせてから書く**。
  実装 HTML だけを見て書くと、WF に残る古い描画(設計10 では仮属性「社員ID」)
  との差分が漏れる。対象ページの PDF テキストを先に抽出して照合すること
- **複数ファイル納品時は、変更の有無にかかわらず毎回全ファイルを提示する**。
  口頭参照(「前回版のまま」)はダウンロード漏れを誘発する(設計10 で発生)
- **人待ちの確認・依頼事項は発生した時点で §4 台帳に記録する**。スレッドを
  跨ぐため、WF 完成では閉じない
- **他文書から申し送りの節番号を参照しない**。申し送りはスレッドごとに全面
  更新されるローリング文書のため、節番号は次スレッドで宙に浮く。過去の決定の
  経緯を引きたい場合は「申し送りの git 履歴」と書く(正本のある決定は
  正本側を参照する)

### ファイル体制(踏襲)

**既存ファイルは GitHub から直接読み出す方式。**

- マスター: `https://github.com/topicmaker-git/Pages` の `choi/` ディレクトリ(public、raw 取得可)

  raw 取得不可。必要なファイルは**ユーザーがメッセージ添付で都度渡す**運用。必要分のみ

### 検証環境の注意(踏襲)

- **mermaid 検証**: mermaid-cli は Chrome 不在・root sandbox で失敗する。
  `npm install -g @mermaid-js/mermaid-cli` の上、puppeteer 設定
  (`{"args": ["--no-sandbox"]}`)を `-p` で渡して実行し、**exit code と
  出力 SVG の実在を必ず確認**すること
- **SVG 検証**: XML 妥当性(ElementTree)+ 画像化して目視
- **PDF 検証**(WF PDF の検収に毎回必要):
  - `pdftotext` は無い。**PyMuPDF(`fitz`)** を使う
    (`pip install pymupdf --break-system-packages`)
  - **断ち切れ検査は描画要素の座標で行う**: `page.get_drawings()` /
    `page.get_text("dict")` の bbox から各ページの最大 X を取り、
    A4 幅(595pt)超過を列挙する
  - フッタの総ページ数表記と実ページ数の**オフバイワンは既知の挙動**。
    指摘対象にしない
  - **手元に来る WF PDF は master の最新コミット時点**。ゲートキーパーは
    高橋さんのローカル(コミット前後・push 前)を見ているため、ページ番号や
    反映状態がずれたら**版のずれ(push 未達)をまず疑う**(設計10 で複数回発生)
