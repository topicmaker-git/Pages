### 運用ルール(設計22 で追加)

- **アプリに読ませる指示書(vibe/)には編集者向けの記述を一切載せない**。
  出典・改訂追跡・「現物例は未収載」のような改訂予定・裁定日は、読者
  (アプリ開発者)にとって情報量を持たない。置き場は `vibe/改訂メモ.md`
- **保証規定は実装の挙動を確認してから書く**。「`analysis_status` が
  `done` なら全デッキで `analysis` が非 null」と書いたが、実装は対象なし・
  失敗デッキをスキップしたうえで無条件に `done` にする。保証できない
  性質は、受け手側の中断規定(状態と実値の両方を見る)で受ける
- **API ドキュメントの記述が実装より古いことがある**。unit.md の
  `analysis_status` 説明(投稿時 `processing` → `done`、解析は必ず走る)は
  #444 ②(登録時生成の停止)以前のままで、これを現況と読んで Q6 の
  決着形を誤読した。issue の実機確認記録が API ドキュメントより新しい
  場合はそちらが現況
- **用いるアプリと用いないアプリを分けて規定する**。任意の付加データ
  (解析データ)について「無くても動作すること」を一律に課すのは、用いると
  決めたアプリへの余計な要求。用いるアプリはその前提条件(状態 `done`)を
  メディアと同じ資格の門として確認し、満たさなければ提供を中断する

### ファイル体制(踏襲)

**既存ファイルは GitHub から直接読み出す方式。**
