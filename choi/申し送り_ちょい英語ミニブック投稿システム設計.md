### 運用ルール(全スレッド共通・踏襲)

- **確認 → 合意 → 編集 → grep/レンダリング検証 → 出力**。黙って方針を変えない
- **単一情報源原則**。同じ規則を複数箇所に書くときは正本を1つ決め、他は参照
- 整合チェックは grep での一括突き合わせ(言い換え表現込み)
- **API 正**(佐藤さんの API ドキュメントが正)。ただし API 内部矛盾は「書き損じ」を特定のうえ確認
- **仕様を書く前に実装の現況を確認する**。要求を新規に決めるのか、
  既決を文書に写すだけなのかを最初に切り分けること
- 佐藤さん管轄(`org_invitation.md` / `course_invitation.md`)は**読み取り専用**
- 番号(§・UC・画面ID・エッジID)は**付け替えず末尾追記**。削除時は欠番として明記。
  **枝番で挿入する**。挿入前に該当番号の既存有無を grep すること
- WF修正仕様 = Claude Design 向け指示書。画面遷移図 SVG 4枚 = **Claude が直接編集**(viewBox `0 0 1123 794`)
- 編集後は毎回ハングル混入チェック
- **切り分けの根拠に使う「規定あり側」も、規定として成立しているかを検証する**
- 実装現況の一次判定はゲートキーパー調査で消化し、佐藤さんには改修依頼と
  運用判断のみ残す / 人間チームへの伝達は見出し1〜2行+仕様書参照 /
  拡張属性列の中身はファミリー区画(choi/ab/)で文書化 — の設計12 追加分は
  そのまま踏襲(詳細は git 履歴の設計12→13 版)
- WF・mermaid・PDF・複数ファイル納品・台帳記録・申し送り参照禁止の各ルールは
  設計10/11 で追加のとおり踏襲(詳細は git 履歴)

### 運用ルール(設計13 で追加)

- **エラー処理・応答形式を仕様に書くときは、当該 API の実応答規約を確認して
  から書く**。本システムの Maker API はアプリケーションエラーも **HTTP 200**
  で返し、`status: 0` + `error` で表現する(`Maker/Web.pm` `render_api`。
  `status_code` はどこにも設定されていない)。設計13 では一般的な HTTP 規約を
  前提に発動条件を書いて検収で差し戻された(補正A)。「実装の現況を確認する」
  ルールの適用対象に**応答規約そのもの**が含まれることの明文化
- **実装済み機能に隣接する裁定依頼は、裁定案を書く前に API ドキュメント確認
  またはゲートキーパー調査を先行させる**。コースメンバー除外は「仕様の穴」
  として裁定依頼が来たが、実際はバックエンド実装済み(`member/remove`)で、
  裁定案の前提が崩れた
- **Claude Design 一時指示書で NOTE 追記を指示するときは、本文に
  「NOTE — 」プレフィックスを直書きしない**(テンプレートの自動付与と
  二重になり紙面に出る。設計13 の v2 バッチで修正した実績)
- **ゲートキーパー検収の差分件数は、仕様側 Claude の編集台帳(論理編集
  箇所数)と突き合わせる。機械カウントは `git diff -U0` のハンク数を基準と
  する**(既定の `-U3` は近接編集を併合して少なく見せる。設計13 では
  検収報告4箇所 → 再検収5箇所 → 実編集6箇所という食い違いが発生。
  1行差分は目視で数え漏れやすい)
- 納品ファイルの提示リンクはマルチバイトファイル名で稀に化ける。
  一時ファイル(コミット対象外)は ASCII 名で運用してよい(正本の日本語名は
  変更しない)
- **実行環境(コンテナ)はターン間でリセットされ得る。長文成果物は同一ターン
  内で高橋さんに渡し切ること**(設計13 で巻き戻りが発生。**outputs への納品も
  巻き戻りの対象になり得た**。生き残ったのは Pages 作業コピーへ着地済みの
  ファイルのみで、復旧可能性の境界は「高橋さんに渡り切ったか」。渡し切れない
  場合はコンテキストから全文復元できる状態を保つ)

### ファイル体制(踏襲)

**既存ファイルは GitHub から直接読み出す方式。**

- マスター: `https://github.com/topicmaker-git/Pages` の `choi/` ディレクトリ(public、raw 取得可)
- セッション冒頭で clone または raw.githubusercontent.com から一括取得して展開
  (URL の日本語ファイル名は percent-encode。**fetch 系ツールは URL 長超過で
  弾くことがあるため、コンテナの curl / sparse clone が確実**)
- **佐藤さんの API ドキュメントは別リポジトリ** `topicmaker-git/enHack-Analysis`(**private**)。
  raw 取得不可。必要なファイルは**ユーザーがメッセージ添付で都度渡す**運用。
  実装コードの調査はゲートキーパー経由
