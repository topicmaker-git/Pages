### 運用ルール(全スレッド共通・踏襲)

- **確認 → 合意 → 編集 → grep/レンダリング検証 → 出力**。黙って方針を変えない
- **単一情報源原則**。同じ規則を複数箇所に書くときは正本を1つ決め、他は参照
- 整合チェックは grep での一括突き合わせ(言い換え表現込み)
- **API 正**(佐藤さんの API ドキュメントが正)。ただし API 内部矛盾は「書き損じ」を特定のうえ確認
- **仕様を書く前に実装の現況を確認する**。要求を新規に決めるのか、
  既決を文書に写すだけなのかを最初に切り分けること
- 佐藤さん管轄(`org_invitation.md` / `course_invitation.md`)は**読み取り専用**
- 番号(§・UC・画面ID・エッジID)は**付け替えず末尾追記**。削除時は欠番として明記。
  **枝番で挿入する**。挿入前に該当番号の既存有無を grep すること
- WF修正仕様 = Claude Design 向け指示書。画面遷移図 SVG 4枚 = **Claude が直接編集**(viewBox `0 0 1123 794`)
- 編集後は毎回ハングル混入チェック
- **切り分けの根拠に使う「規定あり側」も、規定として成立しているかを検証する**
- 実応答規約の確認(**Maker API はアプリケーションエラーも常に HTTP 200 +
  `status: 0`**)/ 実装済み機能に隣接する裁定依頼は裁定案より調査を先行 /
  Claude Design 一時指示書で「NOTE — 」を本文直書きしない / 検収の差分件数は
  **`git diff -U0` のハンク数**を基準にする / 一時ファイルは ASCII 名で運用可 /
  長文成果物は同一ターン内で高橋さんに渡し切る — の設計13 追加分はそのまま
  踏襲(詳細は git 履歴の設計13→14 版)
- 実装現況の一次判定はゲートキーパー調査で消化し、佐藤さんには改修依頼と
  運用判断のみ残す / 人間チームへの伝達は見出し1〜2行+仕様書参照 /
  拡張属性列の中身はファミリー区画(choi/ab/)で文書化 — の設計12 追加分も
  そのまま踏襲(詳細は git 履歴)
- WF・mermaid・PDF・複数ファイル納品・台帳記録・申し送り参照禁止の各ルールは
  設計10/11 で追加のとおり踏襲(詳細は git 履歴)

### 2.1 サンプルデータ一式(納品物)

AB会話教材のプロトタイプ(万次郎語 HTML + `manifest.json`)の ID1〜5 を、
投稿データ_メディアパック仕様のエクセル投稿形式へ機械変換したもの。
`choi_ab_sample.zip`(2026-08-06 作成)の中身:

| ファイル | 内容 |
|---|---|
| `sampleS_unit.xlsx` | 投稿用エクセル本体。**14列 × 30データ行**(ヘッダ1行) |
| `audio.zip` | 実音声 mp3 **30本**(フラット構成。`id001_a0.mp3` 〜 `id005_b2.mp3`) |
| `image.zip` | `theme001.png` 1枚(デッキ画像・カード画像に兼用) |
| `gen_sample_s.py` | 生成スクリプト(出口検査つき。§2.2) |
| `audio_rename_map.tsv` | プロトタイプ側音声名 → 投稿名の対応表(30件。manifest キー付き) |
| `make_real_audio_zip.sh` | プレースホルダ無音を実音声に差し替えて `audio.zip` を作り直す手順 |

- **構造**: ユニット = カテゴリー / デッキ1件(チャプター「よろしく、英語なら？」)/
  カード5件(シーン「セット1」〜「セット5」)/ カードあたり6行
  (話者 A・B・類似A×2・類似B×2)。**パート未使用のため14列**
  (仕様 §1.2 の最大17列から、パート列と未使用列を落とした形)
- **拡張属性2列(仕様 §1.7.2)を実地で使った初の現物**:
  「カード属性」は各カードの先頭行のみ5件、「デッキ属性」はデッキ先頭行のみ
  1件。値はミニファイ済み JSON 文字列で、記入粒度・パース可否・先頭行以外が
  空欄であることをスクリプト側で検査している
- **この一式が事実上固定した AB教材のキー名**:
  カード属性 = `{"speakers":{"A":…,"B":…}}` / デッキ属性 =
  `{"title_en":…,"title_ja":…}`。**現時点ではサンプルの実装値でしかなく、
  正本はどこにもない**。choi/ab/ の AB教材規約.md で正本化すること(§3)
  (設計15 で規約 §3 へ昇格済み — 必須キー・非空文字列・定義キーのみ
  出力の適合条件つき)
- 「和訳」列は全行空欄(プロトタイプに対応データなし)。「音声ファイル」列は
  全30行必須で、重複なし

### 2.2 生成方法と出口検査

- **`gen_sample_s.py` に仕様の条文単位で検査を埋め込み、全件パスを確認**して
  から引き渡した。主な検査項目: 行数 30(5カード × 6行)/ 話者の並び順 /
  英会話のスラッシュ数と語順訳の空白数の一致 / セル値の前後空白・改行・
  連続空白の不正(仕様のセル値正規化)/ 数値化されず文字列型であること /
  拡張属性2列の先頭行のみ記入・JSON パース可・ミニファイ一致 / シーン名列の
  並び / 音声参照30件の重複なしと文字集合 / デッキ画像・カード画像の記入行 /
  manifest との対応 / ハングル混入 / 未使用列が空であること /
  `audio.zip` の集合一致とフラット構成
- **音声は2段構え**: スクリプトはまずプレースホルダ無音で `audio.zip` を組み、
  `make_real_audio_zip.sh` で実 mp3(`s{n}_{a|b}{0-2}.mp3`)を投稿名へ
  コピーして差し替える。対応関係は `audio_rename_map.tsv` が正
- 変換元は private なプロトタイプ資産のため、**再現には
  `manifest.json` と元エクセルが要る**(Pages 側だけでは再生成できない)
